## 2. '논술 LAB 운영 확인' 개선안 — 2안 비교 + 권장

### 안 A (권장) — 상태 카드 4개 + 정상 시 축소(하이브리드)
```
논술 LAB 운영 확인                                   [새로고침]
┌──────────┬──────────┬──────────┬──────────┐
│ 실패      │ 처리 중   │ 재시도 대기 │ 신규 피드백 │
│  0        │  1        │  1        │  0        │
│ 최근7일접수│ 현재      │ 현재      │ 전체·대기 │   ← 항목별 기간 뱃지
│ (중립)    │ (주의?)   │ (주의?)   │ (중립)    │   ← 0=중립 / >0=주의색
│ 실패 내역→│ 미완료→   │ 운영 현황→│ 피드백→   │
└──────────┴──────────┴──────────┴──────────┘
ⓘ 대기 건수만으로 장애를 판정하지 않습니다. 통합 경고(장기 미완료·결과 누락·차감 이상)는
   확인 불가 — 개별 첨삭 상세에서 확인.           (작은 글씨·툴팁)
▸ 모두 정상(실패0·장기미완료 없음)일 때: 한 줄로 축소 "논술 LAB 운영: 이상 없음 · 처리중 1 · [펼치기]"
```
- 각 지표 = **큰 숫자 + 라벨 + 기간 뱃지 + tone**. `KpiTile`의 `tone:'ok'|'warn'|'danger'|'info'` **재사용**. 0=중립(ok/info), >0=실패는 danger·처리중/대기는 warn, 단 **"장애" 단정 문구 금지**(주의 색 + "확인 필요").
- **정상 시 축소 / 이상 시 우선**: 실패>0 또는 장기 미완료 있으면 해당 카드 **상단·danger**로 부각 + [상세]; 전부 정상이면 **1줄 접힘**.
- 판정 주의·통합경고 "확인 불가"는 **툴팁/작은 글씨**로 내려 높이 축소.

### 안 B — 조건부 경고 리스트(기본 최소)
```
논술 LAB 운영: 이상 없음 · 처리중 1 · 재시도 1          [자세히]
(이상 시) ⚠ 최근7일 실패 2건 — [실패 내역]  ⚠ 60분+ 미완료 1 — [확인]
```
- 평상시 **1줄**, 이상(실패>0/장기 미완료)일 때만 경고 항목 펼침. 가장 간결하나, 상시 수치(처리중/대기) 가시성은 낮음.

### 권장: **안 A(하이브리드)**
- 이유: ① KPI 카드 시스템과 **일관**(tone 재사용) ② 4개 수치 **상시 한눈** ③ 정상 시 축소·이상 시 우선(안 B 장점 흡수) ④ **항목별 기간 뱃지**로 §1-B 혼동 해소 ⑤ 기존 정직 카피 유지. 신규 데이터 없음(동일 RPC 응답 재구성).

## 3. KPI·기간 필터 개선안

### 3-1. KPI 영역 (Owner §3)
- 현재 6카드(전체 가입/총 공부시간/첨삭권 사용/희망대학 등록/결제 주문/미처리 문의) 한 줄, `KpiTile`(tone·href·note) — 구조 양호. 개선:
  - **역할 분리 유지:** 운영 strip(장애·조치)과 KPI(성장·활동)는 **별도 블록**으로 두되(현재도 분리됨), strip을 KPI **위**에 고정(이상 시 먼저 보이게) — 현재 순서 유지.
  - 수치 가독성: 숫자 크게·라벨 작게(카드 내 위계). 미처리 문의 tone=warn(>0) 이미 적용(CODE) → 동일 규칙을 strip과 통일.
  - 모바일: 6카드 → 2열 그리드 반응형(현재 한 줄은 좁은 화면서 과밀 우려).
- **운영 상태와 KPI를 하나의 카드 시스템으로 무조건 통합하지 않음**(Owner §3): tone만 공유, 블록은 분리.

### 3-2. 기간 필터 (Owner §4) — 3안 비교
| 안 | 내용 | 평가 |
|---|---|---|
| A 전체 공통 1개 | 모든 영역 한 기간 | ✗ 회원구성(all)·문의(현재)·strip(d7)의 **서로 다른 집계 기준**을 왜곡 |
| **B (권장) 상단 공통 + 영역별 개별** | KPI와 "학습·입시 집계"의 **중복 d30 2개를 1개로 통합**, 회원구성은 자체(all) 유지, 문의·strip은 고정 기준 라벨 | ✓ 중복 제거 + 기준 명확 |
| C 각 영역 독립 | 현행 | △ 지금처럼 d30 2개 독립 → 불일치 오해 |
- **권장 B:** 현재 **`kpiPeriod`와 `period`가 둘 다 d30인데 독립** → **하나의 "대시보드 기간"으로 통합**(KPI + 학습·입시 집계 동시 구동). 회원구성은 "가입 기준"이라 의미가 달라 **자체 기간 유지**(라벨 "가입 기간"). 문의="현재 대기", strip="실패 7일/처리중·대기 현재"로 **기준 뱃지 명시**.
- 목적은 "필터 합치기"가 아니라 **집계 기준 명확화**(Owner §4): 각 수치에 **적용 기간 뱃지**(선택 기간 / 전체 / 현재 대기)를 붙인다.
